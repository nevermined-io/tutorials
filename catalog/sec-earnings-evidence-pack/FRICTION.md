# SEC evidence-pack DevEx friction log

The Apple run used Production Live on 2026-09-15. Raw paid responses and request IDs remain in the private `out/` folder. The first pass stopped at the search step; a bounded retry and a full repeat after the script fix are recorded in [BUILD_LOG.md](BUILD_LOG.md).

| Step | Expected | Observed behavior and reproduction | Impact | Fix or proposed fix; acceptance check |
| --- | --- | --- | --- | --- |
| Compose EDGAR search path | The Catalog's advertised `POST /edgar-search/search` path can be appended to its slug base. | `POST /router/route` with `slug:edgar-search`, `path:/edgar-search/search`, `body:{q:"Apple"}` returned upstream 404, `paid:false`, no payment record. The merchant base already includes that path. | A developer copying the endpoint row gets no search evidence and must inspect Router path composition. | The runner now sends an empty `path` for this slug. Retrying with the same request ID returned upstream 200 and a Settled $0.008 payment; the full repeat passed. Catalog should expose whether an endpoint is already part of the service base. Acceptance: its copyable recipe reaches a paid 2xx response without trial-and-error. |
| Construct request body | Catalog detail gives typed input fields or an official wrapper schema. | `edgar-search` detail has `discovery:null` and no body schema. `{q:"Apple"}` came from a prior demo and worked in the paid retry, but the Catalog alone did not teach it. | Builders must leave Catalog or guess a paid request. | Add body schema or a validated example to service detail and MCP `get_service`. Acceptance: a fresh builder can form the working `{q}` request from Catalog alone. |
| Plan sub-cent budget | Displayed merchant price and delegation-cap consumption use a clear scale. | Each of five calls settled at $0.008, totaling $0.040 merchant charges; the 10¢ delegation consumed 5¢, one whole cent per sub-cent call. Compare `/router/payments` and `/delegation/:id` after the full run. | A 4¢ ledger estimate can leave insufficient delegation headroom for five purchases. | Show cap accounting alongside merchant cost in tutorials/outcomes and preserve at least one cent per planned call. Acceptance: a builder can predict why five $0.008 charges consume 5¢ of cap. |
| Map paid response wrappers | Catalog detail identifies the delivered response shape. | EDGAR and Alpha Vantage paid bodies were wrapped in `body.data`; the first offline builder treated this as an assumption. The full run verified the mapping for all five calls. | Until sampled, an evidence pack can silently omit valid facts. | The builder now records the mapping for each source and leaves unknown fields unavailable. Acceptance: a repeat run populates filing accession/date, XBRL values, EPS and income without raw PII in the public sample. |
| Inspect exact price before purchasing | A builder can compare the actual 402 quote with a per-call budget. | The opaque Router settles the merchant's 402 inside `/route`; the caller sees the $0.008 listing and the payment receipt afterward, with no public quote-only route. | Dynamic price drift can only be stopped by the delegation cap, not a client quote check. | Add a non-spending quote or enforced per-call maximum. Acceptance: an over-budget quote is refused before a payment is created. This larger API fix remains open. |
| Retry an ambiguous response | A retry does not create a second charge. | The first search 404 had no payment; the same request ID was reused when the path was corrected. There was one Settled search payment. | A fresh ID after a timeout could double-charge. | Save request JSON privately and reuse its ID only after ledger reconciliation. Acceptance: the corrected retry has one payment row and the full repeat completes. |

No cross-team issue owner or linked issue has been assigned yet; the schema/path and quote-preflight rows need Catalog/API triage before that acceptance work can be considered done.
