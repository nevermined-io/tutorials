# Developer friction log

## 2026-09-16 — Catalog-from-a-harness run (delta blues, AI-written lyrics)

Findings from driving the four-service pipeline (`brave-search-via-mpp`, `suno-mpp`, `fal-ai-mpp`, `2s-io`) directly from an agent harness against **Production Live**, via the Router slug-invoke surface (`/api/v1/router/svc/<slug>/<subpath>` + `X-Router-*` headers) under one erc4337 delegation. Ordered by severity.

| Area | Expected | Observed and reproduction | Impact | Fix and acceptance |
| --- | --- | --- | --- | --- |
| Request-body schema missing | The Catalog tells me the JSON body each endpoint wants. | `ai-catalog.json` and `GET /api/v1/catalog/services/<slug>` expose endpoints as `{path, method, priceLabel, description}` only — no input schema, no example body. Suno `generate-music` 400'd twice: `model:"V3_5"` isn't in the allowed set `[V6,…,V4]`, and `callBackUrl` is required and I'd omitted it — only sunoapi.org's own docs revealed either. | An agent **cannot call a service first-try**; it must trial-and-error 400s (and, on x402, non-free failures) just to learn the schema. Defeats the "discover + pay autonomously" promise. | Add a machine-readable `inputSchema` (JSON Schema) and/or `exampleRequest` per endpoint to the feed and detail endpoint; ideally the Router validates and returns a helpful 400. Accept when an agent can construct a valid body from Catalog data alone. |
| Empty-body 400s | A validation error names the bad/missing field — `auth.md` promises typed `BCK.<MODULE>.<NNNN>` + `message`/`hint`/`category`. | Suno `generate-music` and `2s-io /api/ai/chat` returned a **body-less 400** (only `x-correlation-id`). The typed-error contract is **not honored on Router-proxy passthrough** responses. | Blind guessing, no self-correction; directly caused the wasted probing above. | Never return a body-less 4xx from the Router proxy. Propagate the upstream error body, or synthesize a Router error naming the expected fields / allowed enums for that slug+path. Honor the `BCK.*` + `hint` contract on proxy responses. |
| Async services undocumented + idempotency footgun | The "from a harness" guide tells me how to drive an async service. | Suno (the flagship media service) is async: `generate-*` → `taskId` → poll `get-*-status`. Two hidden traps: (a) `generate-music`/`generate-lyrics` **require `callBackUrl`** even when you intend to poll (a placeholder is fine); (b) each status poll needs a **fresh `X-Router-Request-Id`** — reusing one returns the first cached status forever, so a naive poller hangs and keeps paying $0.005/poll. | The most-used media service is unusable without out-of-band knowledge; a naive poller stalls on a stale status and burns paid calls. | Document the async pattern (generate → poll with a fresh request-id per poll, placeholder `callBackUrl` OK). Consider a Router "await" mode that polls internally and returns the result inline under one charge. |
| 2s.io model naming undiscoverable; 5xx still charged | A documented model id / models list; failed upstream calls are free. | Bare ids (`gpt-4o-mini`) → 400; provider-prefixed (`openai/gpt-4o-mini`) → **accepted but 502** (backend down) — and the charge **settled anyway** as status `Issued` (~$0.001 each), ~1.5¢ lost with **no deliverable**. No models endpoint, no naming doc. | Can't pick a model without paid probing; billing on a gateway 502 that is the service's fault is the sharpest trust edge. | Expose a models list / document the naming; and **do not settle (or auto-refund)** merchant charges when the upstream returns 5xx / never a 2xx. |
| "From a harness" doc is a manifesto, not a runbook | The page alone lets me make a call. | It has principles + links but not: the delegation-create request/response shape, the `X-Router-Target-Slug`/`-Delegation-Id`/`-Request-Id` header contract, or the `svc/<slug>/<subpath>` form. Worse, the Router quickstart documents a **different** interface (`POST /api/v1/router/route` with a JSON body) — the two docs disagree on the calling convention. | A developer following only that page cannot complete a call, and finds two divergent Router APIs. | Add a copy-paste recipe: create delegation, call a service **both** ways (proxy + `X-Router-Target-Slug`, and `svc/<slug>/<subpath>`) with the header table, read the receipt. Reconcile with the quickstart so there is **one** canonical convention. |
| Delegation hides funding wallet / balances | I can see which wallet/chain funds a call and whether I'm funded. | `GET /api/v1/delegation/<id>` returns spend/cap but `wallet`/address is null. Funding is per-chain (MPP→Tempo, x402→Base); x402 fails "less kindly" with no pre-check, and `402 BCK.ROUTER.0009` doesn't echo the address it checked. | Opaque funding; a run can fail deep because funds are on the wrong chain, with an error that can't tell you so. | Return the funding wallet + per-chain balances on the delegation object; add a preflight ("service settles on rail X / chain Y; your balance there is Z"). |
| Price drift: listed vs settled | Listed price ≈ what I pay. | `2s-io describe-image` listed **$0.018**, settled **$0.045**. `settledPriceLabel` exists on the detail object but was null for several services. | Budgeting is unreliable. | Surface a recent `settledPriceLabel` prominently and/or a live quote before the call. |

**What worked well (keep):** discovery is genuinely free and complete enough to pick a service (slug, price band, endpoints, health); the `svc/<slug>/<subpath>` + `X-Router-*` form is clean once you know it, and idempotency via `X-Router-Request-Id` is the right primitive; the delegation cap is enforced server-side exactly as promised; the `/api/v1/router/payments` ledger is an excellent audit trail with real tx hashes; `fal-ai-mpp` and `brave-search-via-mpp` were first-try successes, and `2s-io describe-image` (Claude Haiku) worked well once chat was abandoned.

## 2026-09-15 — earlier bounded Live repeats

| Step | Expected | Observed and reproduction | Impact | Fix and acceptance |
| --- | --- | --- | --- | --- |
| Router receipt | A settled charge prints in dollars. | On the first 2026-09-15 Live run, `amount:35000` (six-decimal USDC atomic units) printed as `$35000` for a $0.035 Brave charge. Run the former receipt expression against the Router payments response. | Builders cannot tell whether the run stayed within its budget. | `run-demo.sh` now divides `amount` by 1,000,000. A local fixture and the second bounded Live run printed `$0.035` for Brave; resolved. |
| Suno completion | A paid generation job produces a downloadable song at roughly its advertised generation price. | The same run needed five Router-paid status checks at $0.005 each after a $0.105 generation charge. A `taskId` arrived before the audio URL. | Generation alone understates total spend and does not prove the deliverable. | The runner allows a bounded number of status checks under a capped delegation and requires an HTTPS audio URL and nonempty downloaded file. Accept when a repeat produces the audio and all polling charges appear in the receipt. |
| Publishing an example | A repeat preserves the existing public representative media until new files are reviewed. | The former runner wrote directly to checked-in `song.mp3` and `album-cover.jpg`. | A failed or unreviewed repeat could replace working public samples. | New media goes to ignored `out/`; both September 15 repeats left tracked media untouched. Reviewed artifacts can be published deliberately; runner fix resolved. |

The first September 15 run returned audio and cover and saved both files privately; nine payments Settled for $0.1705. A second bounded Live run after the receipt and timing fixes also delivered both artifacts, printed correct dollar amounts and an 8-second first-result time, and settled seven payments totaling $0.1605. Both runs used two rails and chains.
